# CNC AI Ecosystem

**Отдельная разработка прекращена. Основной проект — [CNC Assistant](https://github.com/DmitriiKonovalovLull/cnc-assistant).**

Базовая intent-классификация, контракты меток и исправленная span-level оценка NER собраны в [модуле cnc_ml](https://github.com/DmitriiKonovalovLull/cnc-assistant/tree/main/cnc_ml). Его обучение и CLI проверяются отдельными тестами.

Это выборочный перенос: прежний API, Transformers, retrieval и Celery-эксперименты целиком не интегрированы. Их исходники сохранены здесь для истории. [Решения по объединению](https://github.com/DmitriiKonovalovLull/cnc-assistant/blob/main/docs/CNC_CONSOLIDATION.md).

Ниже описана прежняя структура прототипа; новые изменения следует делать в основном проекте.

Экспериментальный Python-бэкенд для помощника по ЧПУ. Здесь собраны API, загрузка справочных данных, поиск по базе знаний и обучение моделей для классификации запросов.

## Устройство

- `api/` — FastAPI-приложение и обработчики запросов;
- `data_pipeline/` — загрузка страниц, PDF и преобразование данных;
- `knowledge_base/` — поиск и обратная связь;
- `ml_core/training/` — обучение и оценка моделей;
- `ml_core/inference/` — классификация намерения и извлечение сущностей;
- `tasks/` — фоновые задачи Celery;
- `config/`, `db/` — настройки и подключение к базе.

Для классификации предусмотрены Transformer и TF-IDF + LinearSVC. Карта меток сохраняется вместе с моделью: порядок классов при обучении и распознавании должен совпадать. Артефакты по умолчанию находятся в `ml_core/models/intent_classifier/`.

## Быстрая проверка

Тесты используют NumPy, PyTorch и joblib, а вместо Transformers и настроек приложения подключают локальные заглушки. Загрузка моделей и подключение к сервисам не нужны:

```powershell
python -m pip install -r requirements-test.txt
python -m unittest discover -s tests -v
```

## Полное окружение

Зависимости перечислены в `requirements.txt`. Для API и фоновых задач нужны PostgreSQL, Redis, дополнительные ML-пакеты и конфигурация окружения. `docker-compose.yml` описывает предполагаемую схему сервисов, но пока не является проверенным способом запуска: есть ссылки на отсутствующие файлы и несогласованные зависимости. Воспроизводимая установка всего стека остаётся задачей разработки.

## Оценка моделей

Вход обучения — одинаковые по длине списки `queries` и `intents`. Для стратифицированного разбиения каждому классу нужны минимум два примера, а размер каждой части должен вмещать все классы.

В репозитории пока нет опубликованного benchmark-набора с происхождением данных и подтверждёнными результатами. Для сравнения моделей нужны macro-F1, метрики по каждому классу, анализ ошибок и отдельная тестовая выборка. Нормализованные SVM-оценки не являются калиброванными вероятностями. Часть NER-метрик в `validation.py` пока представлена заготовками.

## Работа с конфигурацией

Не выводите значения подключения и ключей в журналы. Загружайте joblib-артефакты только из доверенного источника: их десериализация может исполнять код. Внешнее размещение API требует отдельной проверки аутентификации, CORS и доступа к файлам.
